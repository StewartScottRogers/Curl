## New gaps

- GF-0001 In process, Curl never runs TcpConnector: no CONNECT tunnel, no HAProxy header, no .onion refusal, no name-resolution or --resolve/--connect-to failures (Critical)
- GF-0002 In process, Curl opens a new connection for every request, so connection-reuse cases see [DISCONNECT], local port -1 and the wrong verdict for the second response (Critical)
- GF-0003 On Windows the NTLM type-1 message is SSPI's (flags 0xa2088207 plus VERSION), but curl -V does not list SSPI, so the !SSPI cases run and differ (High)
- GF-0004 After a 401 that the server closes the connection on, the authenticated retry is written to the dead connection and never resent on a fresh one (Critical)
- GF-0005 With --anyauth or --proxy-anyauth, a -T upload or -F form that draws a 401/407 is never resent with credentials (High)
- GF-0006 With --digest (or Digest against a proxy), the first POST/PUT sends its body instead of Content-Length: 0 (High)
- GF-0007 -T - (stdin) is read whole and sent with Content-Length, not chunked; no Expect: 100-continue, and no exit 25 under HTTP/1.0 (High)
- GF-0008 A Location with spaces or raw UTF-8 bytes is encoded differently from curl, or rejected (Critical)
- GF-0009 A user Host: header is not used for cookie matching, is kept on a redirect to another host, and a lower-case 'host:' does not remove it (High)
- GF-0010 A cookie set for a trailing-dot public suffix is sent, and a -b name=value cookie follows a redirect to another host (High)
- GF-0011 --url @file and --url @- are taken as a literal URL instead of a list of URLs to read (High)
- GF-0012 Malformed or unusual response heads give the wrong exit code (HTTP/0.9 under -I, header starting with whitespace, 100 without a final response, NUL in a trailer) (High)
- GF-0013 --skip-existing skips the transfer silently; curl writes 'Note: skips transfer, "<file>" exists locally' (Medium)
- GF-0014 --max-filesize stops on a redirect body that is not kept, and does not stop a decompressed body that grows past the limit (High)
- GF-0015 --retry does not follow a 429's Retry-After as curl does (resend, --fail, --retry-max-time warning) (High)
- GF-0016 -J with -L does not take the file name from the last Location, and -OJ --no-clobber --retry differs (High)
- GF-0017 --compressed mishandles 'Content-Encoding: none' and a broken deflate header (High)
- GF-0018 -F multipart bodies differ: custom Content-Type, several files in one -F, quoted file names with , ; " (High)
- GF-0019 -T with a glob and several --output: stdout differs from upstream's %EMPTY expectation (High)
- GF-0020 -K: a missing file's message omits the path, and a Unicode quote in a config file is read differently (High)
- GF-0021 --variable ... {{name:json}} encodes a Unicode string differently (stderr) (Medium)
- GF-0022 -D % (headers to stderr) writes nothing (High)
- GF-0023 -w '\n' written to stdout on Windows ends in CR LF where upstream expects LF (High)
- GF-0024 --url-query passes a user's lower-case %3d through instead of normalising it to %3D (High)
- GF-0025 With Expect: 100-continue, the POST body is not sent when the server answers early and closes (Critical)
- GF-0026 --location-trusted --anyauth through a proxy does not send Basic credentials to the redirect's new host (Critical)
- GF-0027 -C N --fail against a 416 whose Content-Range says the file is complete exits 22 instead of 0 (High)
- GF-0028 A host of only zero-width characters is sent instead of failing with exit 3 (High)
- GF-0029 Curl lists ECH in Features; the Windows reference build does not (Medium)
- GF-0030 Curl lists GSS-API in Features; the Windows reference build does not (Medium)
- GF-0031 Curl lists HTTP2 in Features; the Windows reference build does not (Medium)

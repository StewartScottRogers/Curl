# CurlSurface: transfer options for the Kafka broker schemes

curl's generic transfer options (`-v`, `-o`, `-O`, `-w`, `--fail`, `--fail-with-body`, `-m`) for `kafka` and `kafkas`,
run through the real curl command line in process against `KafkaReferenceBroker`
(`Curl.Conformance.Extended.UnitTests/CurlSurface/Transfer/Brokers/Kafka/`, one case file per scheme and the shared
checks in `KafkaTransferChecks`). Each answered transfer consumes partition 0 of topic `orders`, two records `a` and
`b`, to its high watermark, writing each value and a line feed (ADR-1076); `kafkas` runs over the harness's TLS route
with a self-signed certificate and `-k`. Expected values come from curl's manual page for curl 8.22.0
(curl.se/docs/manpage.html) and the extension's ADRs: the extension maps no broker error to exit 22, so a broker's
OFFSET_OUT_OF_RANGE ends with exit 8 under `--fail` and `--fail-with-body` as without them (ADR-1218). IDs are
`CurlSurface:Kafka<option>-<n>`, `-1` for `kafka` and `-2` for `kafkas`.

| CurlSurface:KafkaVerbose-1 | MUST | `kafka`: `-v` writes curl 8.22.0's connection line (`* Established connection to localhost (127.0.0.1 port N) from ...`) on standard error, and standard output holds the records alone (manual, "-v"). | KafkaTransferSurfaceCases.Verbose_Consumed_WritesTheConnectionLineOnStandardErrorAndOnlyTheRecordsOnStandardOutput |
| CurlSurface:KafkaOutput-1 | MUST | `kafka`: `-o file` in a temporary directory writes the records to the file and nothing to standard output (manual, "-o"). | KafkaTransferSurfaceCases.Output_Consumed_WritesTheRecordsToTheFileAndNothingToStandardOutput |
| CurlSurface:KafkaRemoteName-1 | MUST | `kafka`: `-O` (under `--output-dir`) writes the records to a file named after the URL path's last segment, the partition `0`, and nothing to standard output (manual, "-O"). | KafkaTransferSurfaceCases.RemoteName_Consumed_WritesTheRecordsToTheFileNamedAfterThePartition |
| CurlSurface:KafkaWriteOut-1 | MUST | `kafka`: `-w` writes `%{exitcode}` 0, an empty `%{errormsg}`, `%{url}` and `%{url_effective}` as given, `%{scheme}` the URL's scheme, `%{remote_ip}` 127.0.0.1, `%{remote_port}` the port, `%{size_download}` the bytes written and `%{time_total}` 0.000000 on an injected clock that never moves, after the records (manual, "-w"). | KafkaTransferSurfaceCases.WriteOut_Consumed_WritesEveryVariableAfterTheRecords |

# S3 requirement matrix (part 1 of 2: REST API operations)

Curl's `s3://` client (`Curl.Extended.Protocol.S3.UnitLibrary`) measured against the Amazon S3 API Reference
(docs.aws.amazon.com/AmazonS3/latest/API) and the Amazon S3 user guide's "Virtual hosting of buckets" and Regions
(BL-4498). The cases run curl in process against `Curl.Conformance.Extended.UnitLibrary/S3/S3ReferenceEndpoint`,
which accepts any well-formed `Authorization` header; signature version 4 is part 2, [S3-Signing.md](S3-Signing.md)
(BL-4499), which plugs its verification in through `IS3RequestAuthorizer`.

| ID | Level | Requirement | Covered by |
|----|-------|-------------|------------|
| S3:GetObject-1 | REQUIRED | GetObject is `GET /{Key}` on the bucket; the response body is the object. | S3ObjectCases.Download_GetsTheKeyFromTheVirtualHostedBucket |
| S3:CommonHeaders-1 | REQUIRED | Every request carries `Host` naming the endpoint (and the bucket, virtual-hosted style). | S3ObjectCases.Download_GetsTheKeyFromTheVirtualHostedBucket |
| S3:PutObject-1 | REQUIRED | PutObject is `PUT /{Key}` with the object as the body. | S3ObjectCases.Upload_BelowThePartSize_IsOnePutWithItsLength |
| S3:PutObject-2 | REQUIRED | PutObject carries `Content-Length` (S3 refuses a request without it). | S3ObjectCases.Upload_BelowThePartSize_IsOnePutWithItsLength |
| S3:ObjectKeys-1 | MUST | The key in the URI is percent-encoded once, every byte but the unreserved ones and `/` (UriEncode). | S3ObjectCases.Download_KeyWithSpaceAndPlus_IsPercentEncodedOnce |
| S3:ErrorResponses-1 | MUST | A failure is a 3xx, 4xx or 5xx status with an `Error` body (`Code`, `Message`); the client reports it as a failure (curl: exit 22). | S3ObjectCases.Download_MissingKey_ReportsTheErrorCodeAndExits22 |
| S3:ErrorResponses-2 | MUST | `NoSuchBucket` (404) is a failure. | S3ObjectCases.Download_MissingBucket_Exits22 |
| S3:CreateMultipartUpload-1 | REQUIRED | CreateMultipartUpload is `POST /{Key}?uploads`; its `InitiateMultipartUploadResult` names the `UploadId` the later requests use. | S3MultipartUploadCases.Upload_FromThePartSize_CreatesUploadsPartsAndCompletesInOrder |
| S3:UploadPart-1 | REQUIRED | UploadPart is `PUT /{Key}?partNumber=N&uploadId=ID`, `partNumber` from 1 to 10,000. | S3MultipartUploadCases.Upload_FromThePartSize_CreatesUploadsPartsAndCompletesInOrder |
| S3:UploadPart-2 | MUST | Every part but the last is at least 5 MiB. | S3MultipartUploadCases.Upload_FromThePartSize_CreatesUploadsPartsAndCompletesInOrder |
| S3:UploadPart-3 | MUST | A part that fails ends the upload as a failure; it is not completed. | S3MultipartUploadCases.Upload_PartFailing_StopsWithoutCompletingAndExits22 |
| S3:CompleteMultipartUpload-1 | REQUIRED | CompleteMultipartUpload is `POST /{Key}?uploadId=ID`. | S3MultipartUploadCases.Upload_FromThePartSize_CreatesUploadsPartsAndCompletesInOrder |
| S3:CompleteMultipartUpload-2 | MUST | Its `CompleteMultipartUpload` body lists every part's `PartNumber` and the `ETag` UploadPart returned, in ascending part number. | S3MultipartUploadCases.Upload_FromThePartSize_CreatesUploadsPartsAndCompletesInOrder |
| S3:CompleteMultipartUpload-3 | MUST | A `200 OK` whose body is an `Error` is a failure. | S3MultipartUploadCases.Upload_CompletionAnswering200WithAnErrorBody_Exits22 |
| S3:AbortMultipartUpload-1 | SHOULD | Abort an upload that will not be completed, so its parts stop being stored. | n/a: optional ("if used"); curl's client, like the AWS CLI's `s3 cp` on interrupt, leaves the upload to a lifecycle rule |
| S3:ListObjectsV2-1 | REQUIRED | ListObjectsV2 is `GET /?list-type=2` on the bucket. | S3ListingCases.List_OverSeveralPagesWithADelimiter_FollowsEachContinuationToken |
| S3:ListObjectsV2-2 | MUST | `prefix` limits the listing to keys that begin with it. | S3ListingCases.List_KeyEndingInSlash_ListsUnderThatPrefix |
| S3:ListObjectsV2-3 | MUST | With `delimiter`, keys sharing a prefix up to the delimiter roll up into `CommonPrefixes`. | S3ListingCases.List_OverSeveralPagesWithADelimiter_FollowsEachContinuationToken |
| S3:ListObjectsV2-4 | MUST | While `IsTruncated` is true, the next request sends `NextContinuationToken` as `continuation-token`. | S3ListingCases.List_OverSeveralPagesWithADelimiter_FollowsEachContinuationToken |
| S3:VirtualHosting-1 | SHOULD | Requests are virtual-hosted style, `Host: {bucket}.s3.{region}.amazonaws.com`. | S3ObjectCases.Download_GetsTheKeyFromTheVirtualHostedBucket |
| S3:VirtualHosting-2 | MUST | A bucket name with dots is not used as a host label over HTTPS (the certificate cannot match it); it goes path style. | S3AddressingCases.List_BucketWithDots_IsPathStyleOnTheRegionalHost |
| S3:VirtualHosting-3 | REQUIRED | A path-style request names the bucket as the path's first segment, `/{bucket}/{key}`. | S3AddressingCases.List_BucketWithDots_IsPathStyleOnTheRegionalHost |
| S3:Regions-1 | MUST | A bucket is reached at its Region's endpoint, `s3.{region}.amazonaws.com` (`AWS_REGION`). | S3AddressingCases.Region_FromAwsRegion_NamesTheRegionalHost |
| S3:Endpoints-1 | MUST | A custom endpoint (`AWS_ENDPOINT_URL`, `AWS_ENDPOINT_URL_S3`) is used as given, path style. | S3AddressingCases.CustomEndpoint_FromAwsEndpointUrl_IsPathStyleOverHttp |

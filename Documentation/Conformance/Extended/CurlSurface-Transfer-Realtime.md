# CurlSurface: transfer options for the realtime extended protocols

curl's generic transfer options (`-v`, `-o`, `-O`, `-w`, `--fail`, `--fail-with-body`, `-m`) for `grpc`, `grpcs`,
`signalr`, `signalrs`, `socketio`, `socketios`, `webtransport`, `mcp` and `mcps`, run through the real curl command line
in process (`Curl.Conformance.Extended.UnitTests/CurlSurface/Transfer/Realtime/`, one case file per protocol, both its
schemes as data rows, and the shared checks in `RealtimeTransferChecks`). Expected values come from curl's manual page
for curl 8.22.0 (curl.se/docs/manpage.html) and each extension's ADRs: gRPC fails a grpc-status other than 0 with
exit 22 (ADR-1133), SignalR a completion with an error (ADR-1084), Socket.IO a refused namespace (ADR-1035) and MCP a
tool result with `isError`, whose content it still writes (ADR-1074). Each fails with exit 22 with or without
`--fail`; those options concern HTTP response codes, and these errors arrive inside a successful HTTP exchange.
`webtransport` runs over HTTP/3 and the harness has no WebTransport reference server yet: its rows are `n/a` until
BL-4607 adds one. IDs are `CurlSurface:<option>-<scheme>-<n>`, the scheme in the ID so the transfer parts never clash.

# CurlSurface: curl's transfer options for the storage schemes

curl's generic transfer options `-v`, `-o`, `-O`, `-w`, `--fail`, `--fail-with-body` and `-m` for the storage schemes `az`, `abfs`,
`abfss` (`AzureStorageExtension`), `gs`, `s3` and `oci`, checked through `Curl.Console` in process (`InProcessCurl`)
against each scheme's reference server over TLS on port 443 (`ReferenceRoute.Tls`, `-k`), on a fake `TimeProvider`
(`StorageTransferClock`) that moves only when a case advances it. The cases are in
`Curl.Conformance.Extended.UnitTests/CurlSurface/Transfer/Storage/`, one file per scheme, every check in
`StorageTransferChecks`. Expected values come from curl's manual page for curl 8.22.0 ("-v", "-o", "-O", "-w",
"--fail", "--fail-with-body", "-m", "EXIT CODES") and, for the exit code of a service's error status, from ADR-1090
(s3), ADR-1093 (oci), ADR-1099 (gs) and ADR-1105 (az, abfs, abfss). The `-v` and `--fail-with-body` cases fail for every
storage scheme and are listed in `KnownFailures.txt` with BL-4657 to BL-4660. IDs are `CurlSurface:<option>-<scheme>-<n>`.

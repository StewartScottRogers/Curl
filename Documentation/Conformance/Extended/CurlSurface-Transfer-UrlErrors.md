# CurlSurface: URL errors for every extended scheme

curl's URL errors for every scheme an extension serves, run through the real curl command line in process with no
reference server (`Curl.Conformance.Extended.UnitTests/CurlSurface/Transfer/UrlErrors/`, one case file per extension,
its schemes as data rows, and the shared checks in `UrlErrorChecks`). Expected exit codes come from curl's manual page
for curl 8.22.0 (curl.se/docs/manpage.html, "EXIT CODES" 3, 6 and 7); the error text is what curl 8.22.0 writes for an
`http://` URL of the same shape, measured with `Record-CurlExchange.ps1`. A malformed URL is a port past 65535, a `%`
not followed by two hex digits in the host, or a space in the host. An unresolvable host is one under `.invalid`, the
only names the harness does not resolve (BL-4619); `s3` and `gs` name their endpoint in `AWS_ENDPOINT_URL` and
`STORAGE_EMULATOR_HOST`, since their host is a bucket. A refused connection is port 1, which no reference server
answers; over UDP the harness's datagram connector gives the reason. `demo` stands for a `curl-proto-<scheme>` helper
scheme (ADR-1142), with a helper program on PATH; no case starts a program. IDs are
`CurlSurface:<check>-<scheme>-<n>`.

# Curl.Cli.UnitLibrary

The command-line layer: turning the arguments curl was given into settings, and refusing
them with curl's own messages and exit code when they are wrong. `Curl.Console`'s
`CurlCommandRunner` calls `CommandLineParser.Parse` and builds each transfer from the result;
it does not yet pass on `Range`, `ResumeFrom` or `MaxFileSize` (task BL-095).

## What lives here

| Type | What it does |
| --- | --- |
| `CommandLineParser` | `Parse(arguments)` walks the arguments once and returns a `CommandLineParseResult`. Short options bundle (`-sS`), a value letter takes the rest of its bundle (`-ofile`) or the next argument, long options match exactly and accept `--name=value`, the first `--` ends option parsing, and every other argument is a URL. An empty URL argument is refused as blank; an option's value, empty or not, goes unchanged to the row's applier, which decides whether to refuse it. Stops at the first refusal. Warning lines a row adds while applying its value are carried on the result, accepted or refused. A command line read without refusal that names no URL is refused as `curl: (2) no URL specified`; an empty command line is accepted, because curl answers it differently. `Parse(arguments, pathExists, passwordPrompt, dataFileReader)` takes the check `--cacert` uses to ask whether its path exists, the `IPasswordPrompt` asked for the password when the last `-u` names a user with no colon (after the whole command line is read without refusal, before the no-URL check, as curl does), and the `IDataFileReader` that reads a `-d @file` or `-d @-`; `Parse(arguments)` and `Parse(arguments, pathExists)` use `Path.Exists`, true for a file or a directory, `ConsolePasswordPrompt.ForProcessConsole` and `DiskDataFileReader.ForProcess`. |
| `CommandLineOptionTable` | The options the parser recognises, one `CommandLineOption` row each. It holds `--url`, `-s`/`--silent`, `-S`/`--show-error`, `--progress-meter` (negated as `--no-progress-meter`), `-#`/`--progress-bar`, `-o`/`--output`, `-d`/`--data`, `-u`/`--user`, `-t`/`--telnet-option`, `--tftp-blksize`, `--tftp-no-options`, `--create-file-mode`, and the TLS options `-k`/`--insecure`, `--cacert`, `--capath`, `-E`/`--cert`, `--key`, `--tlsv1.2`, `--tlsv1.3`, `--ciphers` and `--tls13-ciphers`, and `-r`/`--range`, `-C`/`--continue-at` and `--max-filesize`. `-o` warns when its file name looks like a flag; `-d`, `-u` and `-t` accept an empty value, as curl does; `-d @file` reads the file, and `-d @-` standard input, dropping every CR, LF and NUL byte, and a file that cannot be read is refused with exit 26; `--cacert` refuses a path at which nothing exists, an empty one included. `-r` and `-C` on one command line are refused, naming whichever came second; `-r` warns, unless `-s` came first, for a value with no dash (and keeps its leading number with a dash appended) or with a character other than a digit, dash or comma. |
| `CommandLineOption` | One row: long name, optional short letter, whether it takes a value, and the `CommandLineOptionApplier` that checks and sets it. Built with `Flag` (no value), `Text` (non-blank text; an empty value is refused with "blank argument where content is expected"), `FileName` (as `Text`, and a value that starts with `-` and is longer than that, `-` alone being standard output, adds `CommandLineWarning.FileNameLooksLikeFlag` and is still taken) or `Value` (any applier; a numeric option's applier uses `CommandLineNumber`, which refuses an empty value as "expected a proper numerical parameter"). |
| `CommandLineOptionApplier` | The delegate a row uses to write its value into `CommandLineOptions`, or to refuse it. It is handed the parse's path-existence check and its `IDataFileReader`. |
| `CommandLineOptions` | The parsed settings: `Urls` (positional and `--url`, in command-line order), `Silent`, `ShowError`, `OutputFiles`, and the ADR-0006 members `PostData` (every `-d` as UTF-8 bytes, or for `@file` and `@-` the bytes read without CR, LF and NUL, joined in order with `&` as curl joins them), `Credentials` (`-u` split at the first colon; with no colon and no leading `;`, the password is prompted for with `Enter host password for user '<user up to any ;>':`), `TelnetOptions` (every `-t` verbatim, in order), `TftpBlockSize` (unclamped) and `TftpNoOptions`, `CreateFileMode` (`--create-file-mode` as a `UnixFileMode`, `null` when not given), and the TLS settings, recorded and not applied: `Insecure`, `CaCertificateFile`, `CaCertificateDirectory`, `ClientCertificate` (`-E` verbatim, `certificate[:password]` not split), `PrivateKey`, `MinimumTlsVersion` (`SslProtocols.Tls12` or `Tls13`, the last of `--tlsv1.2`/`--tlsv1.3` winning, `null` when neither), `Ciphers` and `Tls13Ciphers`; and `Range` (the `-r` text as curl keeps it, parsed into a `ByteRange` by `Curl.Core`'s `ByteRangeParser` at transfer time), `ResumeFrom` and `ResumeFromOutputSize` (`-C` offset, or `-C -`), and `MaxFileSize` (bytes, `0` meaning no limit). |
| `CommandLineParseResult` | Either `Options` (when `IsAccepted`) or `Refusal`, and in both cases `WarningLines`: the warnings curl prints while reading the command line, in order, empty when there are none. `WarningLinesAfterTransfers` holds the warnings curl prints only after the last transfer has ended, so the console must write them then, not with `WarningLines`: `Warning: Got more output options than URLs` when an accepted command line has more `-o` values than URLs and `-s` is not in effect at its end, once however many are left over. Measured with the local curl 8.21.0 on 2026-09-26: `curl -o f -o g file:///Z:/nx` prints `curl: (37) Could not open file Z:/nx`, then the warning. Always empty when refused. |
| `CommandLineWarning` | The warning lines curl prints about a command line it carries on with: `FileNameLooksLikeFlag` gives `Warning: The filename argument '<value>' looks like a flag.`; `RangeHasNoDash` and `RangeHasInvalidCharacter` are curl's two- and three-line `-r` warnings, wrapped at 79 columns as curl wraps them. `MoreOutputOptionsThanUrls` is `Warning: Got more output options than URLs`, which curl prints after the transfers. Lines carry no terminator. |
| `CommandLineRefusal` | The standard-error lines curl prints for a bad command line, `curl: option <as typed>: <reason>` (or `curl: (2) no URL specified`) and the try-help line, with `FileDoesNotExist` putting `curl: The file '<file>' provided to --cacert does not exist` in front of `curl: option <as typed>: is badly used here`, `BadlyUsedHere` giving that line alone, and `ContinueAtExclusiveWithRange` putting `curl: --continue-at is mutually exclusive with --range` in front of it unless `-s` without `-S` came first, with exit code `CurlExitCode.FailedInit` (2). `DataFileUnreadable` is the one refusal with another exit code, `CurlExitCode.ReadError` (26): `curl: Failed to open <file>` (hidden when `-s` without `-S` came first), `curl: option <as typed>: error encountered when reading a file` and the try-help line. Lines carry no terminator. |
| `CommandLineNumber` | `ParseNonNegative` reads a numeric option value and refuses it as curl does ("expected a proper numerical parameter" / "expected a positive numerical parameter"). `--tftp-blksize` uses it. `ParseOctal` reads unsigned octal digits up to a maximum, refusing a larger value as "too large number" and anything else as "expected a proper numerical parameter"; `--create-file-mode` uses it with a maximum of `0777`. `ParseOffset` reads unsigned digits that fit a `long` for `-C`. `ParseSize` reads `--max-filesize`: digits, an optional fraction, and a `b`/`k`/`m`/`g`/`t`/`p` unit, refusing as "expected a proper numerical parameter", "is badly used here" or "too large number" exactly where curl 8.21.0 does. |
| `IPasswordPrompt` | The seam the parser asks for a `-u` password through: one `ReadPassword(prompt)` returning the typed password. |
| `ConsolePasswordPrompt` | The console-backed `IPasswordPrompt`: writes the prompt to standard error, reads keys without echo until Enter (backspace erases), then writes a line terminator, as curl's Windows `getpass_r` does. An unreadable console ends the password. With `DiskDataFileReader`, the only code here that touches `Console`. |
| `IDataFileReader` | The seam the parser reads a `-d @file` through: `TryReadFile(path, out contents)`, false when the file cannot be opened or read, and `ReadStandardInput()` for `@-`. |
| `DiskDataFileReader` | The `IDataFileReader` over `File.ReadAllBytes` and `Console.OpenStandardInput`, injected through its constructor so it is tested without a disk. A missing file, a directory, denied access or a bad path reads as unread. The only code here that touches `File`. |
| `UploadUrl` | Completes the URL of a `-T`/`--upload-file` transfer: when the URL path names no file, appends the local file's base name the way curl's `add_file_name_to_url` does (ADR-0004). Pure string work; never reads the file system. |

## How they connect

`CommandLineParser` looks each argument up in `CommandLineOptionTable`, and the row's
applier writes into a fresh `CommandLineOptions`. Any failure becomes a
`CommandLineRefusal`, and the parser returns it inside a `CommandLineParseResult`
without reading further arguments. Adding an option is a new row in
`CommandLineOptionTable` plus the property it sets on `CommandLineOptions`. How an
empty value is refused depends on the value's type, as in curl, so that check lives in
the row's applier and never in the parser.

## What does not live here

- Writing refusals and warnings to standard error or choosing their newline: the console
  layer does that with `CommandLineRefusal.StandardErrorLines`,
  `CommandLineParseResult.WarningLines` and, after the transfers,
  `CommandLineParseResult.WarningLinesAfterTransfers`. The one exception is `ConsolePasswordPrompt`, which
  writes the `-u` password prompt itself because it must appear before the password is read.
- `-K`/`--config`, `.curlrc`, `--variable` and `--next`: not implemented. `--no-`
  negation is implemented: a `CommandLineOption.NegatableFlag` row is turned off by
  `--no-<name>`, and any other row's `--no-` spelling is refused as curl refuses it.
- URL parsing and validation, and opening output files: other layers, after parsing. The
  only file-system work done here is asking whether the `--cacert` path exists and reading a `-d @file`.
- Applying the TLS settings: `Curl.Console` maps them onto the TLS provider.

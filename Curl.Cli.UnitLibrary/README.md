# Curl.Cli.UnitLibrary

The command-line layer: turning the arguments curl was given into settings, and refusing
them with curl's own messages and exit code when they are wrong. `Curl.Console`'s
`CurlCommandRunner` calls `CommandLineParser.Parse` and builds each transfer from the result;
it does not yet pass on `Range`, `ResumeFrom` or `MaxFileSize` (task BL-095), nor `ConnectTimeout` or `MaxTime` (tasks BL-123 and BL-124).

## What lives here

| Type | What it does |
| --- | --- |
| `CommandLineParser` | `Parse(arguments)` walks the arguments once and returns a `CommandLineParseResult`. Short options bundle (`-sS`), a value letter takes the rest of its bundle (`-ofile`) or the next argument, long options match exactly and accept `--name=value`, the first `--` ends option parsing, and every other argument is a URL. An empty URL argument is refused as blank; an option's value, empty or not, goes unchanged to the row's applier, which decides whether to refuse it. Stops at the first refusal. Warning lines a row adds while applying its value are carried on the result, accepted or refused. A command line read without refusal that names no URL is refused as `curl: (2) no URL specified`; an empty command line is refused with the try-help line alone and exit 2, as curl 8.21.0 does. `Parse(arguments, pathExists, passwordPrompt, dataFileReader)` takes the check `--cacert` uses to ask whether its path exists, the `IPasswordPrompt` asked for the password when the last `-u` names a user with no colon (after the whole command line is read without refusal, before the no-URL check, as curl does), and the `IDataFileReader` that reads a `-d @file` or `-d @-`; `Parse(arguments)` and `Parse(arguments, pathExists)` use `Path.Exists`, true for a file or a directory, `ConsolePasswordPrompt.ForProcessConsole` and `DiskDataFileReader.ForProcess`. None of these reads `.curlrc`; `Parse(arguments, pathExists, passwordPrompt, dataFileReader, defaultConfigFileSearch)` first reads the first readable path `DefaultConfigFileSearch` lists (`DefaultConfigFileSearch.ForProcess` for this process) with `ConfigFileApplier.ApplyDefaultFile`, unless the first argument starts with `-q` or is exactly `--disable`, as curl 8.21.0 does; an empty command line is then accepted when the file names a URL. |
| `CommandLineOptionTable` | The options the parser recognises, one `CommandLineOption` row each. `ecl:<list>` or `ecl:@<file>` apart from the mode, a file that cannot be read warned about and refused as badly used), `--ssl-sessions` (global), `--engine` (`list` asks for the engine list and ends the command line), `--dump-ca-embed` (ends the command line), `--tlsuser`, `--tlspassword` (empty accepted) and `--tlsauthtype` (anything but `SRP` refused as not supported by the installed libcurl), the others refusing an empty value as blank, and the HTTPS-proxy TLS options `--proxy-cert`, `--proxy-key`, `--proxy-cert-type`, `--proxy-key-type`, `--proxy-pass`, `--proxy-ciphers`, `--proxy-tls13-ciphers`, `--proxy-crlfile` (refusing a path at which nothing exists, as `--crlfile` does), `--proxy-pinnedpubkey`, and the negatable `--proxy-ca-native`, `--proxy-ssl-auto-client-cert` and `--proxy-ssl-allow-beast`, each read as its origin counterpart is into its own `Proxy*` property (BL-605), and the SSH options `--pubkey` and `--hostpubsha256` (refusing an empty value as blank, checking nothing else), `--knownhosts` (refusing a path at which nothing exists, as `--cacert` does), `--hostpubmd5` (refusing an empty value as blank and any value not exactly 32 characters long as badly used, hex digits unchecked) and `--compressed-ssh` (negatable), with `--key`, `--key-type` and `--pass` serving SSH as well as TLS (BL-562), and `--proto` and `--proto-redir` (read by `CommandLineProtocolSet`; a value that leaves no scheme is refused as badly used) and `--proto-default` (refusing an empty value as blank and an unknown scheme, `all` included, as "a specified protocol is unsupported by libcurl" with exit 1), and `-r`/`--range`, `-C`/`--continue-at` and `--max-filesize`, and `--connect-timeout` and `-m`/`--max-time`, and `-R`/`--remote-time` (negated as argument skips `.curlrc`), and the transfer-encoding and HTTP version options `--compressed`, `--raw`, `--tr-encoding`, `--ignore-content-length`, `--path-as-is` and `--http0.9` (each negatable with `--no-`), `--request-target` (refusing an empty value as blank), `--ipfs-gateway` (refusing an empty value as blank and accepting any other, since curl checks the gateway only when it rewrites an `--http2`, `--http2-prior-knowledge`, `--http3` and `--http3-only`, which are refused with `CommandLineRefusal.InstalledLibcurlDoesNotSupport` as the Windows curl 8.21.0 refuses them (ADR-0017), and `-4`/`--ipv4` and `-6`/`--ipv6` (neither reversible; the last one wins, without a warning; BL-499). `--data-ascii` is `-d`; `--data-binary @file` and `--json @file` keep the file unchanged; `--data-raw` never reads a file; `--data-urlencode` and `--url-query` split at the first `=` (else the first `@`) and escape the content with `UrlEncodedContent`, and a `--url-query` value starting with `+` is kept verbatim; a file any of them cannot read is refused with exit 26. `-o` and `-D` warn when their file name looks like a flag, and `-D` keeps its value verbatim, `-` (standard output) included; `-d`, `-u` and `-t` accept an empty value, as curl does; `-d @file` reads the file, and `-d @-` standard input, dropping every CR, LF and NUL byte, and a file that cannot be read is refused with exit 26; `--cacert`, `--proxy-cacert` and `--knownhosts` refuse a path at which nothing exists, an empty one included. `-r` and `-C` on one command line are refused, naming whichever came second; `-r` warns, unless `-s` came first, for a value with no dash (and keeps its leading number with a dash appended) or with a character other than a digit, dash or comma. `-z` reads its value with `CurlDateParser` after dropping a leading `-` (if-unmodified-since), `+` or `=` (both if-modified-since); a value that is not a date clears the condition and warns, unless `-s` came first, with `CommandLineWarning.TimeConditionIsNotADate`. `-X` refuses an empty value as blank; `-A` and `-e` accept one. `-H` keeps its value verbatim, empty included, and warns, unless `-s` came first, with `CommandLineWarning.HeaderDoesNotLookLikeAHeader` when it holds neither a colon nor a semicolon; `-H @file` (or `@-`) adds each non-empty line of the file verbatim, warning about none, and a file that cannot be read is refused with exit 26, as for `-d @file`. `--proxy-header` reads its value the same way into its own list, warning with `CommandLineWarning.ProxyHeaderDoesNotLookLikeAHeader`, and cannot be reversed with `--no-`. `--max-redirs` takes `-1` (no limit) or a number from 0 to 2147483647 and refuses anything else as "expected a proper numerical parameter". `-I` after `--no-head`, or `--no-head` after `-I`, is refused as "is badly used here" after curl's two-line "only select one HTTP request method" warning (dropped when `-s` came first). `-F`/`--form` and `--form-string` go to `MultipartFormField`, which fills `FormParts` and selects the multipart form post, so `-F` and `-I` or `--no-head` refuse each other the same way; neither can be reversed with `--no-`. `-f` and `--fail-with-body` replace each other, warning, unless `-s` came first, with `CommandLineWarning.FailDeselectsFailWithBody` or `FailWithBodyDeselectsFail`; `--no-fail` and `--no-fail-with-body` each turn off both. The auth and proxy options (ADR-0026): `--basic` and `--digest` (each negatable with `--no-`, adding or removing their scheme), `--anyauth` (every scheme), `--oauth2-bearer` (refusing an empty token as blank), `-x`/`--proxy`, `--socks4`, `--socks4a`, `--socks5` and `--socks5-hostname` (one proxy slot, the last winning; the `--socks` options refuse an empty value as blank, `-x ''` is accepted), `-U`/`--proxy-user` and `--noproxy` (both accepting an empty value), and `-p`/`--proxytunnel` (negatable), and the netrc options `-n`/`--netrc` and `--netrc-optional` (each negatable with `--no-`) and `--netrc-file` (refusing a path at which nothing exists, as `--cacert` does, and not reversible), which `CommandLineOptions.NetrcUse` turns into curl's choice: optional when `--netrc-optional` is in effect, beside `-n` or `--netrc-file` too, otherwise required when either of those is, otherwise ignored (BL-504), and `--unix-socket` and `--abstract-unix-socket` (`FileName` rows sharing one socket slot, the last winning, recorded as `UnixSocketPath` and `UnixSocketIsAbstract`; an empty path is refused as blank, and neither is reversible; BL-506); none of `--anyauth`, `--oauth2-bearer`, the proxy and `--socks` options can be reversed with `--no-`. The output options (ADR-0029): `-O`/`--remote-name`, `--remote-name-all`, `-J`/`--remote-header-name`, `--create-dirs`, `--clobber`, `--skip-existing` and `--remove-on-error` (each negatable with `--no-`; `--no-clobber` sets `Clobber` to false, BL-492; `--skip-existing` sets `SkipExisting`, BL-493; `--remove-on-error` sets `RemoveOnError`, and it and `-C` on one command line are refused, naming whichever came second, BL-494), `--output-dir` (refusing an empty value as blank, never warning about a flag-like one) and `-w`/`--write-out` (any value, empty included; `-w @file` and `-w @-` read the template as `-d @file` does, and a file with no bytes clears it and warns `Warning: Failed to read <file>`); neither `--output-dir` nor `-w` can be reversed with `--no-`. The retry and speed options: `--retry`, `-Y`/`--speed-limit` and `-y`/`--speed-time` read with `ParseNonNegative`, `--retry-delay` and `--retry-max-time` with `ParseSeconds`, and `--limit-rate` with `ParseSize`, as curl 8.21.0 reads each; `--retry-all-errors` and `--retry-connrefused` are negatable with `--no-`, and none of the value options can be reversed with `--no-`. And `-M`/`--manual` (negatable) and `-h`/`--help` (a `Subject` row, not reversible), which end parsing as `-V` does and set `ManualRequested`, or `HelpRequested` and `HelpSubject` (ADR-0069); a `manual` line in a `-K` file is ignored, and a `help` line there (or in `.curlrc`) goes to `CommandLineParseResult.ConfigFileHelpSubjects`, accepted or refused, and parsing carries on, because curl prints that page as it reads the line (BL-375). And curl's ten no-function options (BL-488): `-2`/`--sslv2`, `-3`/`--sslv3`, `--metalink`, `--npn`, `--ntlm-wb` and `--false-start` (`NoFunctionFlag` rows; the last four also as `--no-`) and `--egd-file`, `--random-file`, `--krb4` and `--krb` (`NoFunctionValue` rows, taking and ignoring a value; `--krb` per ADR-0142, BL-630), each changing nothing and warning, unless `-s` came first, `Warning: --<name> is deprecated and has no function anymore`. And the GSS-API options (BL-630): `--delegation` (`none`, `policy` or `always` in any case into `GssApiDelegation`; any other value, empty included, warns, unless `-s` came first, `Warning: unrecognized delegation method '<value>', using none` and reads as `none`), and `--service-name` and `--proxy-service-name` (`ServiceName` and `ProxyServiceName`, refusing an empty value as blank); none of them is reversible with `--no-`. And the FTP login and CCC options (BL-634): `--ftp-account` and `--ftp-alternative-to-user` (`FtpAccount` and `FtpAlternativeToUser`, refusing an empty value as blank, not reversible), `--ftp-pret` (`FtpSendPret`, negatable), and `--ftp-ssl-ccc` (negatable) and `--ftp-ssl-ccc-mode` (not reversible; it also turns `--ftp-ssl-ccc` on, and `active` or `passive` in any case sets the mode, while any other value, empty included, warns, unless `-s` came first, `Warning: unrecognized ftp CCC method '<value>', using default` and reads as `passive`), which `FtpClearCommandChannel` turns into `Off`, `Passive` (the default mode) or `Active`. And `-:`/`--next` (a `NextGroup` row, ending a bundle, not reversible), which starts a new option group when the current one has a URL and is otherwise refused with `curl: missing URL before --next` (hidden by `-s` without `-S`) and `is badly used here`, or ignored as a `next` line of a config file. `GlobalOptionLongNames` names the rows every group shares; every other row is per-group (BL-508). |
| `CommandLineOption` | One row: long name, optional short letter, whether it takes a value, and the `CommandLineOptionApplier` that checks and sets it. Built with `Flag` (no value), `NegatableFlag` (no value, turned off by `--no-<name>`), `NegatableFlagThatCanRefuse` (as `NegatableFlag`, but either spelling may be refused, as `-I` and `--no-head` are), `UnsupportedFlag` (no value; every spelling refused with `the installed libcurl version does not support this`, as `--http2` is), `Text` (non-blank text; an empty value is refused with "blank argument where content is expected"), `FileName` (as `Text`, and a value that starts with `-` and is longer than that, `-` alone being standard output, adds `CommandLineWarning.FileNameLooksLikeFlag` and is still taken) or `Value` (any applier; a numeric option's applier uses `CommandLineNumber`, which refuses an empty value as "expected a proper numerical parameter"). `Subject` builds a row that takes no value but reads its attached value, or else the next argument, as a subject, and counts in a bundle only as the last letter, as curl reads `-h`. `NoFunctionFlag` and `NoFunctionValue` build rows for options curl still accepts but that do nothing: they change no setting and add `CommandLineWarning.DeprecatedWithNoFunction`; a `NoFunctionFlag` letter ends its bundle (`EndsBundle`), as curl reads `-2s` as `-2` alone. `NegatableFlagTurnedOffByShortName` builds a `NegatableFlag` whose short letter turns it off (`ShortNameTurnsOff`), as curl reads `-N` as `--no-buffer` while `--buffer` sets `NoBuffer` back to false (BL-491). |
| `CommandLineOptionApplier` | The delegate a row uses to write its value into `CommandLineOptions`, or to refuse it. It is handed the parse's path-existence check and its `IDataFileReader`. |
| `CommandLineOptions` | The parsed settings: `Urls` (positional and `--url`, in command-line order), `Silent`, `ShowError`, `OutputFiles` (the `-o` name paired with each URL position up to the last `-o`, `null` where none), `UrlOutputs` (each URL's output, ADR-0029), `UploadFiles` (every `-T` value in order, the Nth uploaded to the Nth URL, empty meaning no upload; the SSH settings `SshPublicKeyFile`, `SshKnownHostsFile`, `SshHostPublicKeyMd5`, `SshHostPublicKeySha256` and `SshCompression`, recorded and not applied; and `AllowedProtocols` and `AllowedRedirectProtocols` (the lowercase schemes `--proto` and `--proto-redir` allow, `null` when not given) and `DefaultProtocol` (the `--proto-default` scheme, lowercase); and `Range` (the `-r` text as curl keeps it, parsed into a `ByteRange` by `Curl.Core`'s `ByteRangeParser` at transfer time), `ResumeFrom` and `ResumeFromOutputSize` (`-C` offset, or `-C -`), `MaxFileSize` (bytes, `0` meaning no limit), and `ConnectTimeout` and `MaxTime` (`TimeSpan?` to the millisecond, `null` when not given, zero meaning no limit), and `RemoteTime` (`true` when the last of `-R`/`--remote-time` and `--no-remote-time` asked for the remote time), and `TimeCondition` (the last `-z` as a `Curl.Protocol.Abstractions.TimeCondition`, `null` when not given or when the last value was not a date), and `RequestMethod` (the last `-X`), `Headers` (every `-H` in order, an `@file` value replaced by its non-empty lines), `ProxyHeaders` (every `--proxy-header`, read the same way), `UserAgent` (the last `-A`, empty meaning no `User-Agent` header) and `Referer` (the last `-e`, `;auto` kept as given), and `FollowRedirects` (`-L` or `--location-trusted`), `SendCredentialsToRedirectHosts` (`--location-trusted`), `MaxRedirects` (50 when not given, `-1` for no limit), `KeepPostAfter301`, `KeepPostAfter302` and `KeepPostAfter303`, `ShowHeaders` (`-i`, or `-I`), `NoBody` (`-I`), `HttpMethodSelected` (the `SelectedHttpMethod` `-I`, `--no-head` or `-F` selected, `None` when none was), `FailMode` (an `HttpFailMode`: the last of `-f` and `--fail-with-body`) and `FailEarly`, and `FormParts` (the `FormPartSpecification` tree `-F` and `--form-string` describe), and `Compressed`, `Raw`, `TransferEncoding`, `IgnoreContentLength`, `PathAsIs`, `AllowHttp09Reply` (`--http0.9`), `RequestTarget` (the last `--request-target`, `null` when not given) and `IpfsGateway` (the last `--ipfs-gateway`, verbatim, `null` when not given) and `HttpVersion` (an `HttpVersionPreference?`: the last of `-0` and `--http1.1`, `null` when neither was given), and `IpAddressFamily` (an `IpAddressFamilyChoice`: `IPv4Only` or `IPv6Only` for the last of `-4` and `-6`, `Either` when neither was given). | `CommandLineParseResult` | Either `Options` (when `IsAccepted`) or `Refusal`, and in both cases `WarningLines`: the warnings curl prints while reading the command line, in order, empty when there are none. `WarningLinesAfterTransfers` holds the warnings curl prints only after the last transfer has ended, so the console must write them then, not with `WarningLines`: `Warning: Got more output options than URLs` when an accepted command line has an `-o`, `-O` or kept `--no-remote-name` with no URL to pair with and `-s` is not in effect at its end, once however many are left over. Measured with the local curl 8.21.0 on 2026-09-26: `curl -o f -o g file:///Z:/nx` prints `curl: (37) Could not open file Z:/nx`, then the warning. Always empty when refused. With `-:`/`--next` groups it holds the warning once for the first group with an output left over and once for each group after it (BL-508). `Groups` lists the option groups to run, `Options` first; `RefusalAfterGroups` is the `no URL specified` or form-and-data refusal curl meets setting up a later group, printed after the groups before it have run (`curl URL --next` runs `URL`, then exits 2). |
| `CommandLineGlobalState` | What every `-:`/`--next` option group of one command line shares: the settings of the options `CommandLineOptionTable.GlobalOptionLongNames` lists (`-s`, `-S`, `-v`, the trace options, `--stderr`, `--fail-early`, `--variable` and the like), the warning lines, the open `-K` files and the groups themselves. Each group's `CommandLineOptions` holds the same instance, so a global option given in any group is in effect in all of them (BL-508). |
| `CommandLineWarning` | The warning lines curl prints about a command line it carries on with: `FileNameLooksLikeFlag` gives `Warning: The filename argument '<value>' looks like a flag.`; `RangeHasNoDash` and `RangeHasInvalidCharacter` are curl's two- and three-line `-r` warnings, wrapped at 79 columns as curl wraps them. `MoreOutputOptionsThanUrls` is `Warning: Got more output options than URLs`, which curl prints after the transfers. `TimeConditionIsNotADate` is curl's two-line warning for a `-z` value that is not a date, the first line ending in a space. `FailDeselectsFailWithBody` and `FailWithBodyDeselectsFail` are curl's one-line warnings when `-f` and `--fail-with-body` replace each other; `OverridesPreviousHttpVersion` is `Warning: Overrides previous HTTP version option`, printed when `-0` and `--http1.1` replace each other; `FailedToRead` is `Warning: Failed to read <file>`, for a `-w @file` with no bytes. `OnlyOneRequestMethod` is its "You can only select one HTTP request method!" warning, wrapped at 79 columns, naming the two methods as curl does (`-I`, `--no-head`, `-F`, and a `-d` body). `PostRequestedWithHead` and `PostRequestedWithGet` are that warning for a `-d`/`--json` body with `-I` or `--no-head`; the parser accepts that command line, and `Curl.Console` refuses it at transfer setup, not while parsing, reading `HttpMethodSelected`, `PostData` and `DataInQuery`. Lines carry no terminator. |
| `CommandLineRefusal` | The standard-error lines curl prints for a bad command line, `curl: option <as typed>: <reason>` (or `curl: (2) no URL specified`) and the try-help line, `EmptyCommandLine` giving the try-help line alone, `FormAndDataBoth` having no lines at all (the command line asks for a form and a `-d` body both, which curl reports with the request-method warning alone, exit 2), with `InstalledLibcurlDoesNotSupport` reading `the installed libcurl version does not support this` (`--http2` and the other options ADR-0017 refuses), `FileDoesNotExist` putting `curl: The file '<file>' provided to <option> does not exist` (for `--cacert`, `--proxy-cacert`, `--knownhosts` or `--netrc-file`, hidden when `-s` without `-S` came first) in front of `curl: option <as typed>: is badly used here`, `BadlyUsedHere` giving that line alone, and `ContinueAtExclusiveWithRange` putting `curl: --continue-at is mutually exclusive with --range` in front of it unless `-s` without `-S` came first, with exit code `CurlExitCode.FailedInit` (2). A file that cannot be read gives the other exit code, `CurlExitCode.ReadError` (26): `DataFileUnreadable` is `curl: Failed to open <file>` (hidden when `-s` without `-S` came first), `curl: option <as typed>: error encountered when reading a file` and the try-help line, and a `-K` file refused anywhere is described under `ConfigFileApplier`. Lines carry no terminator. |
| `CurlHelpText` | The lines `-h` / `--help [subject]` prints, ported from curl 8.21.0's `tool_help` (ADR-0069): the usage page with no subject, every option for `all`, the category list for `category`, a category's heading and options for its name, and `Unknown category provided, ...` with the list for anything else, subjects in any case. The option column is fitted to the terminal width passed in (`DefaultColumns`, 79, when nothing sets one). A subject starting with `-` asks for an option's manual section (`IsOptionSubject`), which `CurlOptionManualSection` prints. |
| `CurlHelpTable` | curl 8.21.0's 274 help rows (option as shown, description, `CurlHelpCategories`), copied from its generated `src/tool_listhelp.c`; it lists every curl option, not only those `CommandLineOptionTable` parses. |

| `CurlManual` | The lines `-M` / `--manual` prints: curl 8.21.0's built-in manual as the reference build printed it, read from the embedded `CurlManual.txt`. |

## How they connect

`CommandLineParser` looks each argument up in `CommandLineOptionTable`, and the row's
applier writes into a fresh `CommandLineOptions`. Any failure becomes a
`CommandLineRefusal`, and the parser returns it inside a `CommandLineParseResult`
without reading further arguments. Adding an option is a new row in
`CommandLineOptionTable` plus the property it sets on `CommandLineOptions`. How an
empty value is refused depends on the value's type, as in curl, so that check lives in
the row's applier and never in the parser.

## What does not live here

- Writing refusals and warnings to standard error or choosing their newline: the console
  layer does that with `CommandLineRefusal.StandardErrorLines`,
  `CommandLineParseResult.WarningLines` and, after the transfers,
  `CommandLineParseResult.WarningLinesAfterTransfers`. The one exception is `ConsolePasswordPrompt`, which
  writes the `-u` password prompt itself because it must appear before the password is read.
- `--next`: parsed into groups here (BL-508); running each group with its own options is `Curl.Console`'s (BL-509). Printing `Note: Read config file from '<path>'` for `-v` from `CommandLineOptions.DefaultConfigFile`, and calling the `.curlrc`-reading `Parse` overload, belong to `Curl.Console` (task BL-243). `--no-`
  negation is implemented: a `CommandLineOption.NegatableFlag` or `NegatableFlagThatCanRefuse` row is turned off by
  `--no-<name>`, and any other row's `--no-` spelling is refused as curl refuses it.
- URL parsing and validation, and opening output files: other layers, after parsing. The
  only file-system work done here is asking whether the `--cacert`, `--knownhosts` or `--netrc-file` path exists and reading a `-d @file`, a `-K` file or a `--variable name@file`, all through `IDataFileReader`. `--variable %name` reads the process environment (ADR-0064).
- Applying the TLS settings: `Curl.Console` maps them onto the TLS provider.

# Curl.Cli.UnitLibrary

The command-line layer: turning the arguments curl was given into settings, and refusing
them with curl's own messages and exit code when they are wrong. `Curl.Console`'s
`CurlCommandRunner` calls `CommandLineParser.Parse` and builds each transfer from the result;
it does not yet pass on `Range`, `ResumeFrom` or `MaxFileSize` (task BL-095), nor `ConnectTimeout` or `MaxTime` (tasks BL-123 and BL-124).

## What lives here

| Type | What it does |
| --- | --- |
| `CommandLineParser` | `Parse(arguments)` walks the arguments once and returns a `CommandLineParseResult`. Short options bundle (`-sS`), a value letter takes the rest of its bundle (`-ofile`) or the next argument, long options match exactly and accept `--name=value`, the first `--` ends option parsing, and every other argument is a URL. An empty URL argument is refused as blank; an option's value, empty or not, goes unchanged to the row's applier, which decides whether to refuse it. Stops at the first refusal. Warning lines a row adds while applying its value are carried on the result, accepted or refused. A command line read without refusal that names no URL is refused as `curl: (2) no URL specified`; an empty command line is refused with the try-help line alone and exit 2, as curl 8.21.0 does. `Parse(arguments, pathExists, passwordPrompt, dataFileReader)` takes the check `--cacert` uses to ask whether its path exists, the `IPasswordPrompt` asked for the password when the last `-u` names a user with no colon (after the whole command line is read without refusal, before the no-URL check, as curl does), and the `IDataFileReader` that reads a `-d @file` or `-d @-`; `Parse(arguments)` and `Parse(arguments, pathExists)` use `Path.Exists`, true for a file or a directory, `ConsolePasswordPrompt.ForProcessConsole` and `DiskDataFileReader.ForProcess`. |
| `CommandLineOptionTable` | The options the parser recognises, one `CommandLineOption` row each. It holds `--url`, `-s`/`--silent`, `-S`/`--show-error`, `--progress-meter` (negated as `--no-progress-meter`), `-#`/`--progress-bar`, `-o`/`--output`, `-d`/`--data`, `-D`/`--dump-header`, `-u`/`--user`, `-t`/`--telnet-option`, `--tftp-blksize`, `--tftp-no-options`, `--create-file-mode`, and the TLS options `-k`/`--insecure`, `--cacert`, `--capath`, `-E`/`--cert`, `--key`, `--tlsv1.2`, `--tlsv1.3`, `--ciphers` and `--tls13-ciphers`, and `-r`/`--range`, `-C`/`--continue-at` and `--max-filesize`, and `--connect-timeout` and `-m`/`--max-time`, and `-R`/`--remote-time` (negated as `--no-remote-time`), and `-z`/`--time-cond`, and the HTTP request options `-X`/`--request`, `-H`/`--header`, `-A`/`--user-agent` and `-e`/`--referer`, and the body options `--data-ascii`, `--data-binary`, `--data-raw`, `--data-urlencode`, `--json`, `-G`/`--get` (negated as `--no-get`) and `--url-query`, and the redirect, header and fail options `-L`/`--location`, `--location-trusted`, `--max-redirs`, `--post301`, `--post302`, `--post303`, `-i`/`--show-headers` (and its alias `--include`), `-I`/`--head`, `-f`/`--fail`, `--fail-with-body` and `--fail-early`, every one of them but `--max-redirs` negatable with `--no-`, and `-K`/`--config`, which `--no-config` cannot reverse, and the transfer-encoding and HTTP version options `--compressed`, `--raw`, `--tr-encoding`, `--ignore-content-length` and `--path-as-is` (each negatable with `--no-`), `--request-target` (refusing an empty value as blank), `-0`/`--http1.0` and `--http1.1` (neither reversible; switching from one to the other warns, unless `-s` came first, with `CommandLineWarning.OverridesPreviousHttpVersion`), and `--http2`, `--http2-prior-knowledge`, `--http3` and `--http3-only`, which are refused with `CommandLineRefusal.InstalledLibcurlDoesNotSupport` as the Windows curl 8.21.0 refuses them (ADR-0017). `--data-ascii` is `-d`; `--data-binary @file` and `--json @file` keep the file unchanged; `--data-raw` never reads a file; `--data-urlencode` and `--url-query` split at the first `=` (else the first `@`) and escape the content with `UrlEncodedContent`, and a `--url-query` value starting with `+` is kept verbatim; a file any of them cannot read is refused with exit 26. `-o` and `-D` warn when their file name looks like a flag, and `-D` keeps its value verbatim, `-` (standard output) included; `-d`, `-u` and `-t` accept an empty value, as curl does; `-d @file` reads the file, and `-d @-` standard input, dropping every CR, LF and NUL byte, and a file that cannot be read is refused with exit 26; `--cacert` refuses a path at which nothing exists, an empty one included. `-r` and `-C` on one command line are refused, naming whichever came second; `-r` warns, unless `-s` came first, for a value with no dash (and keeps its leading number with a dash appended) or with a character other than a digit, dash or comma. `-z` reads its value with `CurlDateParser` after dropping a leading `-` (if-unmodified-since), `+` or `=` (both if-modified-since); a value that is not a date clears the condition and warns, unless `-s` came first, with `CommandLineWarning.TimeConditionIsNotADate`. `-X` refuses an empty value as blank; `-A` and `-e` accept one. `-H` keeps its value verbatim, empty included, and warns, unless `-s` came first, with `CommandLineWarning.HeaderDoesNotLookLikeAHeader` when it holds neither a colon nor a semicolon; `-H @file` (or `@-`) adds each non-empty line of the file verbatim, warning about none, and a file that cannot be read is refused with exit 26, as for `-d @file`. `--max-redirs` takes `-1` (no limit) or a number from 0 to 2147483647 and refuses anything else as "expected a proper numerical parameter". `-I` after `--no-head`, or `--no-head` after `-I`, is refused as "is badly used here" after curl's two-line "only select one HTTP request method" warning (dropped when `-s` came first). `-F`/`--form` and `--form-string` go to `MultipartFormField`, which fills `FormParts` and selects the multipart form post, so `-F` and `-I` or `--no-head` refuse each other the same way; neither can be reversed with `--no-`. `-f` and `--fail-with-body` replace each other, warning, unless `-s` came first, with `CommandLineWarning.FailDeselectsFailWithBody` or `FailWithBodyDeselectsFail`; `--no-fail` and `--no-fail-with-body` each turn off both. The auth and proxy options (ADR-0026): `--basic` and `--digest` (each negatable with `--no-`, adding or removing their scheme), `--anyauth` (every scheme), `--oauth2-bearer` (refusing an empty token as blank), `-x`/`--proxy`, `--socks4`, `--socks4a`, `--socks5` and `--socks5-hostname` (one proxy slot, the last winning; the `--socks` options refuse an empty value as blank, `-x ''` is accepted), `-U`/`--proxy-user` and `--noproxy` (both accepting an empty value), and `-p`/`--proxytunnel` (negatable); none of `--anyauth`, `--oauth2-bearer`, the proxy and `--socks` options can be reversed with `--no-`. |
| `CommandLineOption` | One row: long name, optional short letter, whether it takes a value, and the `CommandLineOptionApplier` that checks and sets it. Built with `Flag` (no value), `NegatableFlag` (no value, turned off by `--no-<name>`), `NegatableFlagThatCanRefuse` (as `NegatableFlag`, but either spelling may be refused, as `-I` and `--no-head` are), `UnsupportedFlag` (no value; every spelling refused with `the installed libcurl version does not support this`, as `--http2` is), `Text` (non-blank text; an empty value is refused with "blank argument where content is expected"), `FileName` (as `Text`, and a value that starts with `-` and is longer than that, `-` alone being standard output, adds `CommandLineWarning.FileNameLooksLikeFlag` and is still taken) or `Value` (any applier; a numeric option's applier uses `CommandLineNumber`, which refuses an empty value as "expected a proper numerical parameter"). |
| `CommandLineOptionApplier` | The delegate a row uses to write its value into `CommandLineOptions`, or to refuse it. It is handed the parse's path-existence check and its `IDataFileReader`. |
| `CommandLineOptions` | The parsed settings: `Urls` (positional and `--url`, in command-line order), `Silent`, `ShowError`, `OutputFiles`, and the ADR-0006 members `PostData` (every `-d`, `--data-*` and `--json` piece in order, each but a `--json` one after an `&` when the body so far is not empty, as curl joins them), `SendsJson` (any `--json` given), `DataInQuery` (`-G`), `UrlQuery` (every `--url-query` joined with `&`), `Credentials` (`-u` split at the first colon; with no colon and no leading `;`, the password is prompted for with `Enter host password for user '<user up to any ;>':`), `TelnetOptions` (every `-t` verbatim, in order), `TftpBlockSize` (unclamped) and `TftpNoOptions`, `CreateFileMode` (`--create-file-mode` as a `UnixFileMode`, `null` when not given), and the TLS settings, recorded and not applied: `Insecure`, `CaCertificateFile`, `CaCertificateDirectory`, `ClientCertificate` (`-E` verbatim, `certificate[:password]` not split), `PrivateKey`, `MinimumTlsVersion` (`SslProtocols.Tls12` or `Tls13`, the last of `--tlsv1.2`/`--tlsv1.3` winning, `null` when neither), `Ciphers` and `Tls13Ciphers`; and `Range` (the `-r` text as curl keeps it, parsed into a `ByteRange` by `Curl.Core`'s `ByteRangeParser` at transfer time), `ResumeFrom` and `ResumeFromOutputSize` (`-C` offset, or `-C -`), `MaxFileSize` (bytes, `0` meaning no limit), and `ConnectTimeout` and `MaxTime` (`TimeSpan?` to the millisecond, `null` when not given, zero meaning no limit), and `RemoteTime` (`true` when the last of `-R`/`--remote-time` and `--no-remote-time` asked for the remote time), and `TimeCondition` (the last `-z` as a `Curl.Protocol.Abstractions.TimeCondition`, `null` when not given or when the last value was not a date), and `RequestMethod` (the last `-X`), `Headers` (every `-H` in order, an `@file` value replaced by its non-empty lines), `UserAgent` (the last `-A`, empty meaning no `User-Agent` header) and `Referer` (the last `-e`, `;auto` kept as given), and `FollowRedirects` (`-L` or `--location-trusted`), `SendCredentialsToRedirectHosts` (`--location-trusted`), `MaxRedirects` (50 when not given, `-1` for no limit), `KeepPostAfter301`, `KeepPostAfter302` and `KeepPostAfter303`, `ShowHeaders` (`-i`, or `-I`), `NoBody` (`-I`), `FailMode` (an `HttpFailMode`: the last of `-f` and `--fail-with-body`) and `FailEarly`, and `FormParts` (the `FormPartSpecification` tree `-F` and `--form-string` describe), and `Compressed`, `Raw`, `TransferEncoding`, `IgnoreContentLength`, `PathAsIs`, `RequestTarget` (the last `--request-target`, `null` when not given) and `HttpVersion` (an `HttpVersionPreference?`: the last of `-0` and `--http1.1`, `null` when neither was given). And the auth and proxy settings: `AuthSchemes` (the `HttpAuthSchemes` the scheme options ask for, Bearer only with a token, `Basic` when none is left), `BearerToken`, `Proxy` (a `CommandLineProxy`, `null` when not given), `ProxyCredentials` (`-U`, split and prompted for as `-u` is, with `Enter proxy password for user '<user>':`, after the host prompt; `--oauth2-bearer` suppresses the host prompt), `NoProxy` (verbatim) and `ProxyTunnel`. |
| `CommandLineParseResult` | Either `Options` (when `IsAccepted`) or `Refusal`, and in both cases `WarningLines`: the warnings curl prints while reading the command line, in order, empty when there are none. `WarningLinesAfterTransfers` holds the warnings curl prints only after the last transfer has ended, so the console must write them then, not with `WarningLines`: `Warning: Got more output options than URLs` when an accepted command line has more `-o` values than URLs and `-s` is not in effect at its end, once however many are left over. Measured with the local curl 8.21.0 on 2026-09-26: `curl -o f -o g file:///Z:/nx` prints `curl: (37) Could not open file Z:/nx`, then the warning. Always empty when refused. |
| `CommandLineWarning` | The warning lines curl prints about a command line it carries on with: `FileNameLooksLikeFlag` gives `Warning: The filename argument '<value>' looks like a flag.`; `RangeHasNoDash` and `RangeHasInvalidCharacter` are curl's two- and three-line `-r` warnings, wrapped at 79 columns as curl wraps them. `MoreOutputOptionsThanUrls` is `Warning: Got more output options than URLs`, which curl prints after the transfers. `TimeConditionIsNotADate` is curl's two-line warning for a `-z` value that is not a date, the first line ending in a space. `FailDeselectsFailWithBody` and `FailWithBodyDeselectsFail` are curl's one-line warnings when `-f` and `--fail-with-body` replace each other; `OverridesPreviousHttpVersion` is `Warning: Overrides previous HTTP version option`, printed when `-0` and `--http1.1` replace each other; `OnlyOneRequestMethod` is its "You can only select one HTTP request method!" warning, wrapped at 79 columns, naming the two methods as curl does (`-I`, `--no-head`, `-F`, and a `-d` body). Lines carry no terminator. |
| `CommandLineRefusal` | The standard-error lines curl prints for a bad command line, `curl: option <as typed>: <reason>` (or `curl: (2) no URL specified`) and the try-help line, `EmptyCommandLine` giving the try-help line alone, `FormAndDataBoth` having no lines at all (the command line asks for a form and a `-d` body both, which curl reports with the request-method warning alone, exit 2), with `InstalledLibcurlDoesNotSupport` reading `the installed libcurl version does not support this` (`--http2` and the other options ADR-0017 refuses), `FileDoesNotExist` putting `curl: The file '<file>' provided to --cacert does not exist` in front of `curl: option <as typed>: is badly used here`, `BadlyUsedHere` giving that line alone, and `ContinueAtExclusiveWithRange` putting `curl: --continue-at is mutually exclusive with --range` in front of it unless `-s` without `-S` came first, with exit code `CurlExitCode.FailedInit` (2). A file that cannot be read gives the other exit code, `CurlExitCode.ReadError` (26): `DataFileUnreadable` is `curl: Failed to open <file>` (hidden when `-s` without `-S` came first), `curl: option <as typed>: error encountered when reading a file` and the try-help line, and a `-K` file refused anywhere is described under `ConfigFileApplier`. Lines carry no terminator. |
| `CommandLineNumber` | `ParseMinusOneOrMore` reads `--max-redirs`: an optional `-` and digits, from -1 to 2147483647, anything else "expected a proper numerical parameter". `ParseNonNegative` reads a numeric option value and refuses it as curl does ("expected a proper numerical parameter" / "expected a positive numerical parameter"). `--tftp-blksize` uses it. `ParseOctal` reads unsigned octal digits up to a maximum, refusing a larger value as "too large number" and anything else as "expected a proper numerical parameter"; `--create-file-mode` uses it with a maximum of `0777`. `ParseOffset` reads unsigned digits that fit a `long` for `-C`. `ParseSize` reads `--max-filesize`: digits, an optional fraction, and a `b`/`k`/`m`/`g`/`t`/`p` unit, refusing as "expected a proper numerical parameter", "is badly used here" or "too large number" exactly where curl 8.21.0 does. `ParseSeconds` reads `--connect-timeout` and `-m`: whole seconds up to `MaximumWholeSeconds` (2147482, from Windows curl's 32-bit `long`), an optional `.` fraction kept to the millisecond, and anything after the digits ignored, as curl's `secs2ms` does; a value not starting with a digit or with too many seconds is "expected a proper numerical parameter", a `.` without digits that fit a `long` is "too large number". |
| `ConfigFileApplier` | Applies a `-K`/`--config` file in place of the option: reads it through the parse's `IDataFileReader` (standard input for `-`, shown as `<stdin>`), splits it with `ConfigFileSyntax` and applies each line through `CommandLineParser` as if typed on the command line, stopping at the first refused line. A file that cannot be read is refused with exit 26 (`curl: cannot read config from '<file>'`); files nest at most five deep, counting the command line's, as curl's `CONFIG_MAX_LEVELS`. A refused line is reported by every file it passes through as `curl: <file>:<n> config file option '<option>' <reason>`, then `curl: option -K: <reason>`, an unknown option becoming `found an unknown config option`, and a parameter the option does not use is `had unsupported trailing garbage`. |
| `ConfigFileSyntax` | Splits a config file into `ConfigFileLine`s as curl's `parseconfig` does: CR LF read as LF; blank and `#` lines skipped and not counted in line numbers; the option runs from the line's first character to a blank or, when it does not start with `-`, to `=` or `:`; a `"` parameter is unescaped (`\t`, `\n`, `\r`, `\v`, else the character itself) to the closing quote; an unquoted one ends at white space, warning when more than a comment follows it or when it starts with `'`. |
| `MultipartFormField` | Reads one `-F`/`--form` or `--form-string` value into `CommandLineOptions.FormParts`, ported from curl 8.21.0's `formparse`: `name=value`, `name=@file` (or `@file1,file2`, a multipart of files), `name=<file`, `name=(` opening a multipart and `=)` closing it, `--form-string` taking the content as text. Files are named, not read. A value with no `=`, or `=)` with no multipart open, is refused as "is badly used here" after curl's warning. |
| `FormPartParameterReader` | Reads a form part's content word and its `;type=`, `;filename=`, `;headers=` (text, or `@file`/`<file` read through the `IDataFileReader`) and `;encoder=` parameters into `FormPartParameters`, ported from curl's `get_param_part` and `get_param_word`: quoting with `\"` and `\` escapes, blanks trimmed around unquoted words, parameter names in any case, and curl's warnings for trailing data after a quote, an unknown parameter, a parameter the part does not allow and an unreadable header file. |
| `FormPartSpecification` | One form part as the command line described it: `Name` (`null` for none), `Kind` (a `FormPartKind`: `Text`, `FileUpload`, `FileContent` or `Multipart`), `Content` (the text, or the file path, `-` for standard input), `ContentType`, `FileName`, `Encoder`, `Headers` and, for a multipart, `Parts`. |
| `WrappedMessage` | Splits an error or warning message into prefixed lines at 79 columns, as curl's `voutf` does when standard error is not a terminal. Used for the `-K` and `-F` messages and the request-method warning. |
| `IPasswordPrompt` | The seam the parser asks for a `-u` or `-U` password through: one `ReadPassword(prompt)` returning the typed password. |
| `CommandLineProxy` | The proxy a command line names: the `-x` or `--socks*` value as given and the `ProxyKind` that option means. `TryGetKind` reads the scheme before `://` in any case (`http`, `https`, `socks` and `socks4`, `socks4a`, `socks5`, `socks5h`), falls back to the option's kind when there is none, and for any other scheme returns the exit-7 `TransferResult` `Unsupported proxy scheme for '<value>'`, as curl 8.21.0 fails the transfer. |
| `ConsolePasswordPrompt` | The console-backed `IPasswordPrompt`: writes the prompt to standard error, reads keys without echo until Enter (backspace erases), then writes a line terminator, as curl's Windows `getpass_r` does. An unreadable console ends the password. With `DiskDataFileReader`, the only code here that touches `Console`. |
| `IDataFileReader` | The seam the parser reads a `-d @file` (and every other `@file` value) and a `-K` file through: `TryReadFile(path, out contents)`, false when the file cannot be opened or read, and `ReadStandardInput()` for `@-`. |
| `DiskDataFileReader` | The `IDataFileReader` over `File.ReadAllBytes` and `Console.OpenStandardInput`, injected through its constructor so it is tested without a disk. A missing file, a directory, denied access or a bad path reads as unread. The only code here that touches `File`. |
| `CurlDateParser` | `TryParse` reads a `-z` date as libcurl 8.21.0's `curl_getdate` does, ported from `parsedate`: up to six words and numbers (weekday and month names in any case, zone names in capitals, `hh:mm[:ss]`, `+hhmm`/`-hhmm`, `yyyyMMdd`, day, year), a day, month and year required, no time meaning midnight and no zone UTC. The XML remarks list every spelling; the one range it refuses and curl accepts is a year outside 1-9999 (BL-247). |
| `QueryUrl` | Appends the `-G` body, or else the `--url-query` values, to a URL as curl 8.21.0 does. Pure string work; the URL layer parses and validates the result. |
| `UrlEncodedContent` | Escapes `--data-urlencode` and `--url-query` content as `curl_easy_escape` does, a space written as `+`. |
| `UploadUrl` | Completes the URL of a `-T`/`--upload-file` transfer: when the URL path names no file, appends the local file's base name the way curl's `add_file_name_to_url` does (ADR-0004). Pure string work; never reads the file system. |

## How they connect

`CommandLineParser` looks each argument up in `CommandLineOptionTable`, and the row's
applier writes into a fresh `CommandLineOptions`. Any failure becomes a
`CommandLineRefusal`, and the parser returns it inside a `CommandLineParseResult`
without reading further arguments. Adding an option is a new row in
`CommandLineOptionTable` plus the property it sets on `CommandLineOptions`. How an
empty value is refused depends on the value's type, as in curl, so that check lives in
the row's applier and never in the parser.

## What does not live here

- Writing refusals and warnings to standard error or choosing their newline: the console
  layer does that with `CommandLineRefusal.StandardErrorLines`,
  `CommandLineParseResult.WarningLines` and, after the transfers,
  `CommandLineParseResult.WarningLinesAfterTransfers`. The one exception is `ConsolePasswordPrompt`, which
  writes the `-u` password prompt itself because it must appear before the password is read.
- `.curlrc`, `--variable` and `--next`: not implemented. `--no-`
  negation is implemented: a `CommandLineOption.NegatableFlag` or `NegatableFlagThatCanRefuse` row is turned off by
  `--no-<name>`, and any other row's `--no-` spelling is refused as curl refuses it.
- URL parsing and validation, and opening output files: other layers, after parsing. The
  only file-system work done here is asking whether the `--cacert` path exists and reading a `-d @file` or a `-K` file, both through `IDataFileReader`.
- Applying the TLS settings: `Curl.Console` maps them onto the TLS provider.

# BL-733 — Use h2 and h3 alternatives from Alt-Svc and the --alt-svc cache

## Goal

With `--alt-svc`, a cached or freshly advertised `h3` alternative upgrades the next request to that origin to HTTP/3 over QUIC, and an `h2` alternative to HTTP/2, in curl 8.21.0's order of preference and with its fallback when the alternative fails, on every platform.

## Context

- Conformance audit 2026-09-28, row 20; standing rule (root `CLAUDE.md`, "Decisions", 2026-09-28): HTTP/3 includes the Alt-Svc upgrade. BL-623 uses `h1` alternatives; this task adds the other two once HTTP/2 (BL-659) and HTTP/3 (BL-732) run. Cache: BL-622 (`Curl.Core.UnitLibrary`).
- Which alternatives curl uses depends on the HTTP versions the command line allows (curl's `lib/altsvc.c` and `docs/ALTSVC.md` at tag `curl-8_21_0`); record the rule in the XML docs.
- Measure with the official curl build through `Record-CurlExchange.ps1 -NoServer` against a server advertising `Alt-Svc: h3=":<port>"` with an HTTP/3 listener: two runs sharing `--alt-svc f`, `-v` for the second; and the fallback when the h3 port is closed.

## Acceptance criteria

- [x] Measured first as above; stderr and the cache file copied into Notes.
- [x] `Curl.Console.UnitTests` with fake connectors pin the second run connecting over HTTP/3 (and over HTTP/2 for an `h2` entry), the fallback on failure, and the cache written as measured.
- [x] `dotnet build Curl.slnx -warnaserror` is clean, the fast tests pass, and `Measure-CodeQuality.ps1` reports 100% line and branch coverage and no failing member for each library changed.

## Notes

### Which curl

The Windows reference (Git for Windows' curl 8.21.0, Schannel) has no HTTP/2 or HTTP/3, so it never
uses an `h2` or `h3` alternative. As ADR-0144 does for HTTP/3, the reference here is curl.se's build
(WinGet, `curl 8.18.0 … LibreSSL/4.2.1 … nghttp2/1.68.0 ngtcp2/1.21.0 nghttp3/1.15.0`), run through
`Record-CurlExchange.ps1 -Curl <that build>` on 2026-09-29. No local HTTP/3 server exists, so the
upgrade was measured against `https://www.google.com/` (`-NoServer`) and every fallback against the
loopback recorder (`-Tls`). The rule is read from `curl-8_21_0`: `lib/url.c` `url_set_conn_peer`,
`lib/http.c` `Curl_http_neg_init`, `lib/altsvc.c` `Curl_altsvc_lookup`, `lib/cf-https-connect.c`.

### Decided (ADR-0226)

- Every platform uses `h2`/`h3` alternatives, looked up by the version option as `url_set_conn_peer`
  does (table in ADR-0226 and `AltSvcTransferCache`'s remarks). `AltSvcCache.FindForOrigin` (Core) does
  the ordered lookup; `AltSvcTransferCache.ApplyTo` (Console) sets `AltSvcRoute` and `Version`.
- Another host or port: an `h3` entry found under another version gives `Http3Only` (case 3); an `h1`
  or `h2` one gives `Http11`, so ALPN chooses (case 4 falls back to HTTP/1.1 as measured). Same
  version: the option's preference stays (case 5).
- The origin itself: an `h3` entry without a version option gives `Http3`, the race with fallback
  (cases 1 and 2).
- Redirects: `RedirectFollower` takes a `HopAltSvcSelector` and the runner looks each hop up again,
  replacing ADR-0214's "keep the route for the same origin", so a switch to HTTP/3 does not follow a
  redirect to another origin.
- `Documentation/Planning/Decisions` added to `touches` for ADR-0226 (and the note in ADR-0214); no
  task in Doing names it.

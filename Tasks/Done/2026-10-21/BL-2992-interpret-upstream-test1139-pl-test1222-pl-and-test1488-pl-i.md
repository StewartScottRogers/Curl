# BL-2992 — Interpret upstream test1139.pl, test1222.pl and test1488.pl in C# over Libcurl's option table and the vendored libcurl man pages so cases 1139, 1222 and 1488 run

## Goal

Upstream cases 1139, 1222 and 1488 run through C# interpretations of curl 8.22.0's `tests/test1139.pl` (every libcurl option has a man page), `test1222.pl` (deprecation statuses and versions) and `test1488.pl` (symbols-in-versions and man pages agree on added-in versions), with `Libcurl`'s tables standing for the C headers, and pass.

## Context

Split from BL-2851 (2026-10-21, lane 7); the vendored docs come from BL-2990. Follow the pattern of `UpstreamTest971Script.cs` (BL-2865): one script class per file, registered from its own `UpstreamPerlCommandScripts.Test<N>.cs` file (BL-2994), a focused test class per script. Where a check finds `Libcurl` differing from upstream, fix `Libcurl` with a focused unit test in `Libcurl.UnitTests` (ADR-0482) and add those files to `touches`. Before code, run each case with `$env:CURL_UPSTREAM_CASE` and confirm it reaches the perl dispatch rather than being skipped for another reason.

## Acceptance criteria

- [x] Cases 1139, 1222 and 1488 end `Passed` with `$env:CURL_UPSTREAM_CASE='<n>'` on Windows and are on `PassingUpstreamCases.txt`.
- [x] Each script class has focused unit tests, and any `Libcurl` fix has a focused unit test in `Libcurl.UnitTests` that fails without it.
- [x] `dotnet build Curl.slnx -warnaserror` is clean, `dotnet test --filter "TestCategory!=Integration"` passes, and each changed library keeps 100% line and branch coverage and complexity at most 10.

## Notes

- The vendored `include/curl/curl.h` (BL-2990) is upstream's, so 1139 reads its `#define` aliases as the script does; 1488 never reads headers. No `Libcurl` table was needed and no `Libcurl` difference was found, so `Libcurl` is unchanged.
- `curl.1` is generated by `managen` and is in no tarball: 1139 stands in for it with the `.IP` line `managen` writes for each `docs/cmdline-opts/*.md` option file (ADR-0750). Misplaced options are written in ordinal order, where Perl's hash order is undefined.
- `test1222.pl` needs generated `.3` pages; with none (the vendored data) it prints `curl built without the libcurl manual. Skipping test 1222.` and exits 0, as upstream's script does, and so does case 1222 now. With `.3` pages present the interpretation fails with a "not interpreted (BL-3000)" message rather than pass unchecked. The full deprecation check is BL-3000.
- Measured: `Measure-CodeQuality.ps1 -Library Curl.Conformance.UnitLibrary` reports 0 failing members; cases 1139, 1222 and 1488 pass with `CURL_UPSTREAM_CASE`; Curl.Conformance.UnitTests 3970 passed, 0 failed; `dotnet build Curl.slnx -warnaserror` clean.

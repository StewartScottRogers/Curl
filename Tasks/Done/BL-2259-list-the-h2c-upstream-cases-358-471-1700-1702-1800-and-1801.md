# BL-2259 — List the h2c upstream cases 358, 471, 1700, 1702, 1800 and 1801 that pass on Linux and macOS CI, and file a task per cause for the rest

## Goal

Every h2c upstream case (358, 471, 1700, 1702, 1800, 1801) that passes on Linux and macOS is on `Curl.Conformance.UnitTests/PassingUpstreamCases.txt`, and each one that fails there has a task naming its cause.

## Context

BL-2230 put the h2c stand-in for nghttpx (`Curl.Conformance.Http2Server.UnitLibrary`, ADR-0491) on `%HTTP2PORT` through `UpstreamHttp2Server`, gave `%H2CVER` the value `h2c`, and let screening run `http/2` cases. Per ADR-0495 the harness reports `http/2` and `h2c` off Windows only (Curl's Windows build matches curl's Schannel build, which refuses `--http2`), so these cases are `SkippedOnThisPlatform` on a Windows lane and are measured only by CI's Linux and macOS jobs. Read the ratchet rows' messages from the latest green `CI` run on `work/dark-factory` after BL-2230 landed (`gh run view <id> --log` on the Linux and macOS test jobs, rows `test358`, `test471`, `test1700`, `test1702`, `test1800`, `test1801`): "passes and can be listed" means list it; a first difference names a cause.

## Acceptance criteria

- [x] Each of 358, 471, 1700, 1702, 1800 and 1801 whose Linux and macOS ratchet rows say it passes is added to `PassingUpstreamCases.txt` (471 may already be listed).
- [x] Each that fails on Linux or macOS is named in Notes with its first difference, and one task per distinct cause is filed with the board script.
- [x] `dotnet test --filter "TestCategory!=Integration"` is green on Windows.

## Notes

CI's log only says "Skipped" for these rows (no message, no artifact), so the six rows were re-run on Linux (WSL Ubuntu, .NET 10.0.401, Release) with the console logger at detailed verbosity:

- 1700, 1702, 1800: pass; added to PassingUpstreamCases.txt.

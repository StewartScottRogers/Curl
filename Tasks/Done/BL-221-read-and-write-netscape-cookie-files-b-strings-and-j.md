# BL-221 — Read and write Netscape cookie files, -b strings and -j

## Goal

The store loads Netscape cookie files and `-b` strings, drops session cookies under `-j`, and writes a jar byte-equal to curl's.

## Context

- Filed from the Phase 1 HTTP plan (protocol-architect, 2026-09-26), item Q3. Upstream references: https://curl.se/docs/manpage.html and https://curl.se/libcurl/c/libcurl-errors.html; behaviour measured on curl 8.21.0.
- Where a criterion says *measured*, run curl 8.21.0 - the mingw build `/mingw64/bin/curl`, first on PATH, which is the Windows reference (ADR-0009 and the BL-153 ADR) - against a loopback server (the BL-165 recording script `Record-CurlExchange.ps1` once it exists), record the exact command and the bytes it produced in `Notes`, then pin them in a test. Never pin text that was not measured.

## Acceptance criteria

- [x] An unwritable jar gives the measured message.
- [x] `dotnet build Curl.Cookies.UnitLibrary -warnaserror` is clean; `dotnet test --filter "TestCategory!=Integration"` passes and no new test needs `TestCategory=Integration`; `Measure-CodeQuality.ps1` reports 100% line and branch coverage and no failing member for `Curl.Cookies`.

## Notes

- Plan item: Q3 in the Phase 1 HTTP plan (2026-09-26); plan keys in this file were replaced by their task IDs.
- Delivered: `NetscapeCookieFile` (`Read`, `ParseLine`, `Write`, `FormatLine`, `HeaderLines`, `LongestLine`), `CookieFieldRules` (path sanitizing, `__Secure-`/`__Host-` and control-character checks, now shared with `SetCookieParser`), and on `CookieStore`: `AddCookieString`, `LoadCookieFile(Async)`, `WriteCookieJar`, `SaveCookieJarAsync` (through `IFileSystem`, returns `false` silently), `JarCreateMode` (0666, curl's `fopen`). `ICookieStore` is unchanged: `-b` strings ride on `GetCookieHeader`.
- Measured on curl 8.21.0 (`/mingw64/bin/curl`, Schannel, libpsl), 2026-09-26, with `Record-CurlExchange.ps1 -Port 18221` or `curl -b <file> -c - http://127.0.0.1:1/` (the jar is written even when the connect fails). Each is pinned in `NetscapeCookieFileTests` or `CookieStoreTests.CookieFiles.cs`:
  - `-c jar.txt http://localhost:18221/p/x`, response `a=1; Path=/`, `h=2; HttpOnly; Path=/p`, `d=3; Domain=localhost; Max-Age=3600`, `s=4; Secure; HttpOnly`, `q="x y"`: header `# Netscape HTTP Cookie File` / `# https://curl.se/docs/http-cookies.html` / `# This file was generated by libcurl! Edit at your own risk.` / empty line, then newest first, `#HttpOnly_` prefix, `.localhost TRUE` for the domain cookie. Lines end CR LF on this Windows build (text-mode `fopen`); an empty store writes the 135-byte header alone.
  - `-b` file rules: one leading dot off the domain, written back only when includes-subdomains; TRUE columns are "start of TRUE, any case" (empty counts); a path field that starts TRUE/FALSE (case-sensitive, empty counts) is really the secure field with path `/`; expiry = leading digits (`4102444800abc` ok; `+7`, `-5`, empty and 20 digits refused), not capped at 400 days; six fields = empty value, other counts refused; a control char or DEL refuses the name or value but not the domain or path; the first CR ends the line; `#httponly_` is a comment; namesakes replace in place; a line over 4998 characters before its LF (CR counted, last line too) ends the reading.
  - `-j`: session cookies from the file are skipped; cookies received later are still written.
  - `-b 'x=1; y=2'` is sent verbatim; `-b x=1 -b z.txt -b w=3` sends `z=1; x=1; w=3`; strings are never written to the jar; when the 8183-character limit leaves a stored cookie out the strings are left out too, otherwise they are appended past the limit.
  - Unwritable jar (`-c nodir\x.txt`, `-c adir`): nothing on stderr with `-s`, `-sS`, the default, `-v` or `--trace-ascii`, and exit 0. So "the measured message" is no message: `SaveCookieJarAsync` returns `false` and the caller must stay silent.
- For BL-237 (Console wiring): without a `-b` file or `-c`, curl does not store `Set-Cookie` (a `-b x=1` run sent `x=1` on both requests, not the received `a=1`); read the file as Latin-1; write the jar with `Environment.NewLine`.
- Choices (no ADR: each follows measured behaviour or the standing "match the platform's curl" rule): the jar line ending is the platform's (`Environment.NewLine`), because curl writes the jar in text mode (CR LF measured on Windows, LF on Linux and macOS); bytes are handled as Latin-1 so a file round-trips unchanged; the jar is opened with `FileWriteMode.Truncate` rather than curl's temp-file-and-rename.

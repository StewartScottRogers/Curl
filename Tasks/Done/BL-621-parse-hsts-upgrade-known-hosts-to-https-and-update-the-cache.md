# BL-621 — Parse --hsts, upgrade known hosts to https and update the cache from Strict-Transport-Security

## Goal

`--hsts <file>` loads the cache before the transfers, rewrites an `http://` URL (and redirect) to a known host into `https://` (port 80 to 443) as curl 8.21.0 does, updates the cache from `Strict-Transport-Security` on HTTPS responses only, and saves the file when the run ends.

## Context

- Conformance audit 2026-09-28, row 20 (Major). Cache: BL-620.
- URL handling in `Curl.Console/CurlCommandRunner.cs` and the redirect path (`Curl.Core.UnitLibrary/RedirectFollower.cs`); the cookie jar's load-and-save lifecycle (`Curl.Console/CookieEngine.cs`) is the model.
- Measure: `-v` output when a URL is upgraded (curl prints a line), `%{url_effective}`, a header on plain HTTP (ignored), and a missing cache file.

## Acceptance criteria

- [x] Measured first with `Record-CurlExchange.ps1` (`-Tls -k` for HTTPS): the cases above; stdout, stderr, request bytes and the saved file copied into Notes.
- [x] `Curl.Cli.UnitTests` cover parsing; `Curl.Console.UnitTests` pin each measured case through fake file seams and a fake `TimeProvider`.
- [x] `dotnet build Curl.slnx -warnaserror` is clean, the fast tests pass, and `Measure-CodeQuality.ps1` reports 100% line and branch coverage and no failing member for each library changed.

## Notes

- Touches widened to `Curl.Core.UnitLibrary` and `Curl.Core.UnitTests`: the switch of a redirect
  target and the learning from every hop live in `RedirectFollower`, and the run's cache wrapper
  (`HstsTransferPolicy`) sits beside BL-620's `HstsCache`. No task in Doing named either project.
- Decisions: ADR-0218 (one cache per run, shared with or without `--hsts`; file read before and
  written after each transfer of an `--hsts` group; scheme-only switch; redirect switch before
  `--proto-redir`). ADR-0215 was taken by another lane, so this one is 0218.
- Measured 2026-09-29, curl 8.21.0 (x86_64-w64-mingw32) Schannel, `Record-CurlExchange.ps1`:
  1. `-sk --hsts h1.txt -w %{url_effective} https://localhost:18443/`, file missing, response
     `Strict-Transport-Security: max-age=31536000; includeSubDomains`: exit 0, stdout
     `okhttps://localhost:18443/`, file created (CR LF):
     `# Your HSTS cache. https://curl.se/docs/hsts.html` /
     `# This file was generated by libcurl! Edit at your own risk.` /
     `.localhost "20270929 15:45:08"`.
  2. Same file, `-vsk --hsts h2.txt -w %{url_effective}\n http://localhost:18443/a`: stderr starts
     `* Switched from HTTP to HTTPS due to HSTS => https://localhost:18443/a`, then
     `* Host localhost:18443 was resolved.`; stdout `okhttps://localhost:18443/a`; the request is
     `GET /a HTTP/1.1` / `Host: localhost:18443` over TLS on the typed port (the port is kept).
  3. `-s --hsts h3.txt http://localhost:18444/` with the header over plain HTTP: exit 0, the file
     holds the two comment lines only.
  4. `-v -skL https://localhost:18443/` answered `301` with `Location: http://localhost:18443/x`:
     `* Connection #0 to host localhost:18443 left intact` /
     `* Issue another request to this URL: 'http://localhost:18443/x'` /
     `* Switched from HTTP to HTTPS due to HSTS => https://localhost:18443/x`. The Issue line is
     filed as BL-901.
  Earlier in the run (before the cut-off): `--hsts ""` and `--hsts -abc` are accepted without a
  warning, a failed connect still writes the file, and an unwritable file is silently skipped.

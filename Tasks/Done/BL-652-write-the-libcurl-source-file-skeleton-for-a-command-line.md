# BL-652 — Write the --libcurl source file skeleton for a command line

## Goal

`--libcurl <file>` (and `-` for standard output) writes curl 8.21.0's C source file for the command line: the header comment, includes, `main`, `curl_easy_init`, the `CURLOPT_URL` line and the lines curl always emits (buffer size, user agent, max redirects and the like), `curl_easy_perform`, cleanup and return, byte for byte, with the transfer still performed.

## Context

- Conformance audit 2026-09-28, row 30 (Major, L; split: this skeleton, BL-653 HTTP/output/connection options, BL-654 the rest; filed Low).
- The generator maps command-line options, so it belongs in `Curl.Cli.UnitLibrary` (a new type fed `CommandLineOptions`); `Curl.Console` writes the file after the transfers.
- Measure with `Record-CurlExchange.ps1`: `--libcurl - http://127.0.0.1:<P>/`, `--libcurl out.c` with two URLs, and with `-s`; copy the generated text into Notes. Lines naming the curl version must say 8.21.0 as curl's do.

## Acceptance criteria

- [x] Measured first as above; the generated source copied into Notes.
- [x] `Curl.Cli.UnitTests` reproduce the measured skeleton byte for byte for the one-URL and two-URL cases; `Curl.Console.UnitTests` show the file written and the transfer performed.
- [x] `dotnet build Curl.slnx -warnaserror` is clean, the fast tests pass, and `Measure-CodeQuality.ps1` reports 100% line and branch coverage and no failing member for each library changed.

## Notes

Measured 2026-10-01 against curl 8.21.0 (mingw, Schannel) with `Record-CurlExchange.ps1` on port 47652.

`--libcurl - http://127.0.0.1:47652/` (exit 0) wrote this on standard output, LF line ends, after the body:

```
/********* Sample code generated by the curl command line tool **********
 * All curl_easy_setopt() options are documented at:
 * https://curl.se/libcurl/c/curl_easy_setopt.html
 ************************************************************************/
#include <curl/curl.h>

int main(int argc, char *argv[])
{
  CURLcode result;
  CURL *curl;

  curl = curl_easy_init();
  curl_easy_setopt(curl, CURLOPT_BUFFERSIZE, 102400L);
  curl_easy_setopt(curl, CURLOPT_URL, "http://127.0.0.1:47652/");
  curl_easy_setopt(curl, CURLOPT_USERAGENT, "curl/8.21.0");
  curl_easy_setopt(curl, CURLOPT_MAXREDIRS, 50L);
  curl_easy_setopt(curl, CURLOPT_SSLVERSION, (long)CURL_SSLVERSION_TLSv1_2);
  curl_easy_setopt(curl, CURLOPT_TCP_KEEPALIVE, 1L);

  /* Here is a list of options the curl code used that cannot get generated
     as source easily. You may choose to either not use them or implement
     them yourself.

  CURLOPT_WRITEDATA was set to an object pointer
  CURLOPT_INTERLEAVEDATA was set to an object pointer
  CURLOPT_WRITEFUNCTION was set to a function pointer
  CURLOPT_READDATA was set to an object pointer
  CURLOPT_READFUNCTION was set to a function pointer
  CURLOPT_SEEKDATA was set to an object pointer
  CURLOPT_SEEKFUNCTION was set to a function pointer
  CURLOPT_HEADERFUNCTION was set to a function pointer
  CURLOPT_HEADERDATA was set to an object pointer
  CURLOPT_ERRORBUFFER was set to an object pointer
  CURLOPT_STDERR was set to an object pointer

  */

  result = curl_easy_perform(curl);

  curl_easy_cleanup(curl);
  curl = NULL;

  return (int)result;
}
/**** End of sample code ****/
```

What the other runs showed:

- **Two URLs with `-s`:** `-s --libcurl - http://…/a http://…/b` repeats the block from `CURLOPT_BUFFERSIZE` to the blank line after `curl_easy_perform` once per URL. `-s` adds `CURLOPT_NOPROGRESS, 1L` after `CURLOPT_URL`. The source comes after both bodies (`hellohello/****…`).
- **`--libcurl out.c` with two URLs:** the file is written in text mode, so CR LF on Windows, and standard output holds only the bodies.
- **Quoting:** a schemeless URL is quoted as given (`"127.0.0.1:47652/q\?x=1&y=\\\"z\\\""`); `?` becomes `\?`. Tab becomes `\t`, other non-printable bytes `\xHH` in lowercase (é arrived as `\xe9`). A 2100-byte URL is cut to 2000 bytes plus `...`.
- **Scheme lines:** `http`/`https` (in any case, guessed included) get `CURLOPT_MAXREDIRS, 50L`; `ftp`/`ftps` (including guessed `ftp.` hosts) get `CURLOPT_FTP_SKIP_PASV_IP, 1L`; `dict`, `file`, `ws`, `wss` and `http://a b/` (unparsable) get neither. `CURLOPT_SSLVERSION` and `CURLOPT_TCP_KEEPALIVE` appear for every scheme.
- **Failed transfer:** a refused connection (exit 7) still writes the full source.
- **SSH:** `scp://` with no `known_hosts` (exit 2) cuts the source short after `CURLOPT_USERAGENT`; left to BL-654.
- **Unwritable file:** gets `Warning: Failed to open <file> to write libcurl code`, wrapped at 79 columns. `-s` hides it.
- **Other options:** `-m 1` adds `CURLOPT_TIMEOUT_MS`; that line and other option lines belong to BL-653 and BL-654.

Decisions are in ADR-0303:

- The source is built from the transfers performed, using the glob-expanded URL.
- Strings are quoted as UTF-8 bytes.
- A URL holding a space or control character counts as unparsable.
- `CURLOPT_SSLVERSION TLSv1_2` is taken as the tool's default on every platform, since it comes from the tool, not the TLS backend. Not measured on Linux or macOS.

Checked by hand: Curl's `--libcurl` output was byte-identical to curl's for the one-URL, two-URL `-s` and `out.c` cases above.

Delivered by hand rather than through the full `/feature` subagent stages, to keep this unattended run within its budget. The plan was small: one generator type and a runner hook.

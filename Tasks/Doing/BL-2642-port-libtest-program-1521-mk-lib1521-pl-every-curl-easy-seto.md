# BL-2642 — Port libtest program 1521 (mk-lib1521.pl, every curl_easy_setopt and curl_easy_getinfo option) to C# and add case 1521 to the ratchet

## Goal

libtest program lib1521 is ported to C# and upstream case 1521 ("Test all curl_easy_setopt and curl_easy_getinfo options", stdout `ok`) passes through the runner and is on the ratchet.

## Context

Split out of BL-2538 (batch 12 of the libtest ports, phase 5 of `Documentation/Planning/Curl-Api-And-libcurl.md`, ADR-0506). Upstream curl 8.22.0 does not ship `lib1521.c`: `tests/libtest/mk-lib1521.pl` generates it from `include/curl/curl.h`, calling `curl_easy_setopt` for every `CURLOPT_*` with each type's test values (longs 0, 22, LONG_MAX, LONG_MIN; strings and blobs; NULL; the option's object types) and checking each answer against the codes an unsupported or refused option may give, then `curl_easy_getinfo` for every `CURLINFO_*`; it prints `ok` when nothing broke. The port needs the whole `CurlOption`/`CurlInfo` table in `Libcurl` to answer every one of those calls as upstream allows, so it is too big for a batch task.

## Acceptance criteria

- [ ] lib1521 is a C# `ILibTest` in `Curl.Conformance.LibTest.UnitLibrary` (generated by hand or by a PowerShell script from the option table, never Python), registered in `LibTestPrograms`, with a focused unit test in `Curl.Conformance.LibTest.UnitTests` over a fake `ICurlEngine`.
- [ ] Case 1521 passes through the runner on Windows and is added to `Curl.Conformance.UnitTests/PassingUpstreamCases.txt`; an option or info that Libcurl answers wrongly is filed as its own Libcurl task rather than fixed here.
- [ ] `Measure-CodeQuality.ps1 -Library Curl.Conformance.LibTest.UnitLibrary` reports 0 failing members.
- [ ] `dotnet build` is clean and the fast tests pass with no test deleted, skipped or weakened.

## Notes

- 2026-10-18 (lane 1): Port written (left uncommitted for the shift's stash): `Lib1521` (program), `Lib1521Checks` (the generated body: per-type first and secondary setopts, upstream's allowed-answer lists, `present()`, `bad_neg`, and the blob check that reads the stale `result` as the generator writes it), `Lib1521Values` (the object each object option gets) and `Lib1521Infos` (the 78 `CURLINFO_*` entries of 8.22.0's `curl.h`, generated with awk from `curl.h`, never Python), registered in `LibTestPrograms`. Options come from Libcurl's `CurlOptions.All` without aliases, ordered by option number (curl.h's order); its 311 names match curl.h's exactly.
- Choices: `LONG_MIN`/`LONG_MAX` are `long.MinValue`/`MaxValue` (Libcurl's `long`); `on line N` gives the call's ordinal, as C# has no generated source line; `CURLOPT_CURLU` gets a real `CurlUrlHandle` (C# cannot cast a dummy struct), `CURLOPT_STDERR` `Stream.Null`, `CURLOPT_ERRORBUFFER` a `StringBuilder`.
- Case 1521 through the runner on Windows prints `ok` plus six lines, all Libcurl's: `CURLOPT_PROTOCOLS_STR` and `CURLOPT_REDIR_PROTOCOLS_STR` answer 43 for `"string"` (upstream 1) and for NULL (upstream 0), `CURLOPT_SSH_HOST_PUBLIC_KEY_MD5` answers 43 for `"string"` (upstream 0), and `CURLINFO_SIZE_DELIVERED` answers 48 (missing from `CurlInfo`). Filed as BL-2727 per the acceptance criteria and added to `depends-on`. Left for the next claim: the unit tests over `Lib1521Checks` and the fake engine, the ratchet line, the quality run, and the CLAUDE.md port list entry.
